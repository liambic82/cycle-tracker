# Wearable sleep integration

## Optional older history — 0.18.0

Preview 0.18.0 adds separately requested `android.permission.health.READ_HEALTH_DATA_HISTORY`. The SDK feature check controls whether the button is offered; 90/365-day choices appear only after the actual grant (or with fictional sample data). The ordinary sleep permission request still requests only Sleep. Reads recheck history access before and after fetching; denial/revocation leaves recent reads and saved copies available subject to Sleep permission. Existing 500-session/20,000-stage/ten-page limits still apply, so a busy source may need a shorter range. No background or write permission is added.

The owner deferred automatic background syncing and cloud sync. This history extension compiles but needs real-device permission and Inspire 3 data validation. [Android history access](https://developer.android.com/health-and-fitness/health-connect/read-data) · [Consolidated checklist](android-testing.md#0180-consolidated-local-android-test-build). The 0.17.0 description below records the original implementation.

## Decision and status — October 10, 2026

The owner selected **Fitbit first** and identified the testing wearable as **Fitbit Inspire 3**. Preview **0.17.0** implements the first Android Health Connect import. Actual Inspire 3 data availability and native permission behavior require phone validation; automated and browser checks do not establish wearable compatibility. No health permission has been granted by the development agent.

The path is **Fitbit Inspire 3 → Fitbit/Google Health app → Android Health Connect → Cycle Tracker**. Google's documentation says Google Health can write sleep sessions and stages to Health Connect, subject to the user's choices. Cycle Tracker reads those on the phone and retains selected records in its encrypted journal. This adds no Cycle Tracker hosting service or Fitbit credentials. Fitbit/Google's account, device sync and cloud practices remain separate. [Google Health / Health Connect](https://support.google.com/googlehealth/answer/14506680?hl=en). Google lists sleep tracking and stages for the [Inspire 3](https://store.google.com/us/product/fitbit_inspire_3?hl=en_US); this does not guarantee that every night's stages are shared.

Avoid starting a legacy Fitbit Web API integration: Google states those APIs cease support on October 30, 2026 and that Health Connect and Apple Health connections are unaffected. [Google's transition notice](https://support.google.com/googlehealth/answer/14236613?hl=en).

## Implemented first import slice — 0.17.0

Open **Your data → Import wearable sleep** in the installed Android preview. Allow reading sleep, load 7 or 30 recent days, select the source that receives Inspire 3 records, and review one session before importing. No Fitbit package identity is hardcoded: package visibility may leave a package name instead of a friendly label. Confirm the source in Health Connect. Sample mode offers explicitly fictional sessions and never connects to Health Connect.

Only `android.permission.health.READ_SLEEP` is added. The native Expo module uses stable `androidx.health.connect:connect-client:1.1.0`, checks availability/grants on each read, paginates results, rechecks the grant before returning, and bounds reads to 30 seconds. Status/disconnect calls are bounded to 15 seconds. No background/history extension, write, heart-rate or cycle permission is requested. The app minimum becomes Android 8 / API 26 for this SDK; Health Connect itself requires a supported Android 9+ phone. Android 14+ includes Health Connect; older supported devices need the Google app. [Stable SDK release](https://developer.android.com/jetpack/androidx/releases/health-connect) · [Platform and permission setup](https://developer.android.com/health-and-fitness/health-connect/get-started).

Imports preserve source identity, optional device label, source modification/import times, endpoints, available offsets, a captured fallback offset and stage intervals. Waking day uses the source end offset; if absent, the phone zone's offset at session end is captured at first import and retained across travel. A revised source end offset can move a reviewed copy to a new date. Manual sleep stays separate and unchanged. Session span, known asleep/awake intervals and unknown time are distinguished; no vendor score or wakings count is invented. Partial/missing stages mean total sleep is unknown. Overlapping sessions and naps remain separate and are never summed.

Same source/record identity deduplicates repeat imports. Changed source content requires **Update imported copy**; older revisions are refused. Source deletion does not automatically remove a journal copy. Use the waking day's **Review imported sleep** to remove it with confirmation and local Undo; full-entry deletion/Undo also covers it. Disconnect revokes this app's Health Connect permissions but retains copies. Imported data is included in format-7 encrypted backups, CSV and the selected Sleep report section. System connection grants remain device-local and are not backed up.

Leaving, backgrounding or locking clears unimported previews and invalidates late results. Reads allow at most 500 sessions, 20,000 total stages, ten result pages and 3,000 stages per session; the journal permits 100 imports per waking day and sessions up to 72 hours. Unsupported/malformed results fail without applying records. An import exceeding the existing encrypted-journal size limit is rejected before changing the live journal.

Permission-rationale activities support Android versions before and after 14 and show only static sleep privacy information, even while the vault is locked. Before store submission, publish a matching complete privacy policy and finish Play health-data declarations/review. These store steps remain pending.

## Acceptance and later refinements

- Optional Android connection, with an explicit action to request **read sleep** permission only. No cycle, medication, location, broad health access or write-back permission. Recheck grants before reads; handle unavailable/outdated Health Connect, refusal, revocation and an empty result without blocking manual logging. Start with foreground imports rather than additional background access.
- Show available sources and sessions, with a review before applying an import. Check the actual Fitbit/Google Health source identity on hardware rather than hardcoding an unverified package name. A device sync may need to finish before new sleep appears.
- Store source, source record identity, modification information, session start/end and available zone offsets alongside imported values. Use stable identities to avoid duplicates and define behavior for source corrections/deletions. A failed or cancelled import must leave existing entries intact.
- Keep manual entries authoritative until the user explicitly chooses a replacement. Imported sessions need separate provenance and must retain naps/multiple sleeps without silently summing overlaps or replacing the main-sleep record. Define the waking-date mapping for midnight, travel and daylight-saving changes.
- Derive time asleep only from defensible sleep intervals. A session's full start/end span can contain awake time or unknown gaps, so it must not automatically become time asleep. Missing stages do not mean zero wakings. Preserve device estimates as estimates, keep subjective quality user-entered, and do not translate a vendor score into the manual quality scale.
- Include retained imported observations and provenance in encrypted backup/restore, readable exports, date filtering and deletion/Undo. Connection grants remain device-local. Disconnect should stop future reads and clearly distinguish permission removal from deleting previously imported copies.
- Verify permissions, source availability, repeated imports, edits/deletions, partial stages, overlaps, time zones, manual conflicts, lock/cancellation and offline behavior automatically and on the Pixel 7 / Galaxy Z Flip5 test setup with a real Fitbit source. Follow current Play health-permission declaration requirements before store submission.

Android's official sleep guide describes `SleepSessionRecord`, optional stages and the `android.permission.health.READ_SLEEP` permission. The SDK and system must be checked for feature availability rather than assuming a phone OS version guarantees usable records. [Health Connect sleep guide](https://developer.android.com/health-and-fitness/health-connect/experiences/sleep) · [SleepSessionRecord reference](https://developer.android.com/reference/android/health/connect/datatypes/SleepSessionRecord).

## Later platforms

Other Android providers may become available through the same Health Connect route, but each source needs validation. iOS would use a separate HealthKit adapter and its permission flow. The computer browser cannot directly query the Android phone's Health Connect store: version 0.17.0 can display imported data after an encrypted journal backup is transferred. Automatic cross-device sync remains a separate roadmap feature, not a promise of this integration.

The implementation requires device validation; it is not a claim that an Inspire 3 connection has already passed or that every source supplies every field. Automatic background imports, older-history access and automatic deletion reconciliation remain outside this first slice.
